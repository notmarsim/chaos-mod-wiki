# Multiblock Viewer backend

The Viewer is a read-only construction aid. It never places blocks, consumes building ingredients, edits a machine's inventory, changes its port configuration, or force-loads a chunk. Native structure validators run through read-only adapters after the incremental cell/interface checks succeed.

Default energy settings are a 256,000 FE buffer and a shared input limit of 2,048 FE/t across all faces. Exactly one operating cost applies per tick: 4 FE in standby, 8 FE while a detailed menu preview is open, or 32 FE while any online owner's project or provisional placement is projecting. Projection has priority over preview and standby. Insufficient energy suspends presentation and validation while preserving saved projects.

Projects live in the overworld `chaosmod_multiblock_viewer_projects` SavedData, independently of the block inventory. Every project records its owner, definition, normalized size parameters, origin/dimension, rotation, planned substitutions, source UUID/position/dimension, and presentation preferences. Only one project per player is active. Completion counters are rebuilt from the world, never loaded as trusted progress. Breaking a Viewer pauses its active projects; unloading its chunk simply suspends the heartbeat. An owner can resume a saved project on a replacement Viewer explicitly.

Network actions express intentions rather than levels, counts, energy or completion. Creating/resuming/deleting projects and starting library previews require an authorized nearby physical menu. The active project's owner may use remote pause/stop/preferences controls and reopen its menu. Remote menus cannot create or retarget projects. Server checks include ownership, source identity, permissions, valid catalog parameters, legal per-cell overrides, world bounds and a 128-block placement-confirmation range.

Project configuration is sent once on activation. Heartbeats contain aggregate counters and interface/material summaries, not a continuous list of world blocks. `ConfigVersion` and `OverridesCount` allow a client to notice missing planned substitutions and request `project_config`; full resends are owner-only and limited to one per second. Serialized project configuration is limited to 512 KiB before persistence or activation, below the packet NBT limit.

`chaosmod-multiblock-viewer.toml` controls the technical work/cache/render budgets. Server scan work is shared fairly among online owners of a physical Viewer. Statuses use lazy two-bit pages and sparse layer counters rather than allocating one object per block or arrays for the entire height. Unknown unloaded cells never count as air or completion. Long native audits retain their incremental state until completion or relevant changes. Changing projection filters never changes the server's definition of structural validity.

`ViewerGameTests` covers FE transfer and save/load, real Chaos cable conservation, operating costs, ownership, remote versus physical permissions, read-only placement, demolition/replacement, project persistence, incremental Free/Planned checks, long audits, unloaded chunks, compact packet round trips, energy-preserving loot, and fixed material aggregation across differently oriented states.
