# Module and energy display revision

The three single-item module slots and machine demands (3, 6, 9, 12, 24, 48, 96) are unchanged. Power above demand is accepted; each category independently caps its efficiency at 100%.

- Efficiency: `min(1, categoryPower / demand)`.
- Speed: `1 + 2 * speedEfficiency` (maximum 3x).
- Energy per active tick: `base * speed^1.5 * (1 - .75 * energyEfficiency)`, rounded upward once. Existing calibration still applies to the base.
- Stability: `baseLoss * (1 - .90 * stabilityEfficiency)` per unit of work. Work already includes speed and calibration; no second speed multiplier is applied. Fractional stability loss remains saved in NBT. Failure at zero is unchanged.
- Processing uses the existing hundredth-tick progress units; speed is rounded to the nearest progress unit.

Jade is optional. Its energy extension reads the native long values, avoiding the Forge int capability's 2,147,483,647 FE display ceiling. Install Jade on server and client for server-supplied long values. Developer launch option: `-PjadeRuntime`.

Battery capacities remain: Basic 1 MFE, Void 100 MFE, Stellar 100 GFE, Darklight 5 TFE, Nova 100 TFE, Zenith 1 PFE. Standard Forge transfers still use int-sized requests; this integration changes the display, not transport limits.

Machine item tooltips show stored/max FE and preserve long NBT values. Ordinary machine BlockItems receive capacity tooltips too; this does not change which blocks retain energy when broken.

Only Zenith Refiner receives the 1 Darklight Core -> 2 Darklight Bars recipe. Nova remains 1 -> 1. The new recipe is generated by ModMachineRecipeData.

Duality rifts and reality creatures use the saturated violet of the Duality materials and Guardian Core (0x4E00D4).
