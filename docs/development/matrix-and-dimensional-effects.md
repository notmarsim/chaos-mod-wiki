# Matrix throughput and dimensional effects — 2026-11-06

## Matrix diagnosis and correction

Connected Transfer Coils were already summed by `MatrixStructure`. The bottleneck was the fixed, tier-based per-port limit: a single port stopped scaling after roughly two coils. Input and output also consumed the same per-tick budget.

Each port now has access to the full connected-coil throughput. All input ports/faces share one input budget, and all output ports/faces share an independent output budget of the same size. Adding ports does not multiply the installed-coil capacity. Simulated transfers do not consume either budget. Configuration values for individual coil tiers remain unchanged.

The capability, counters, snapshots, UI, and ETA retain exact `BigInteger` energy values. Forge int and long calls saturate only at their API boundary. Removing a cell is blocked when the remaining exact capacity cannot hold the stored energy.

Regression coverage exercises one, two and three coils through real port capabilities; independent input/output; coil removal and revalidation; multiple capability faces; and totals exceeding `Long.MAX_VALUE`.

### Coil capacity rebalance

Default rates now move 5% of a standard same-tier Capacitor Cell per tick. One Coil per Cell can fill or drain the storage in 20 ticks (one second), provided the source, destination and connections sustain the transfer.

| Tier | Cell capacity | Coil input/output rate | Previous 1:1 charge time |
| --- | --- | --- | --- |
| Stellar | 100 GFE | 5 GFE/t | 312.5 seconds |
| Darklight | 5 TFE | 250 GFE/t | 976.56 seconds |
| Nova | 100 TFE | 5 TFE/t | 625 seconds |
| Zenith | 1 PFE | 50 TFE/t | 5 seconds |
| Chaos | 9 EFE | 450 PFE/t | 4.5 seconds |

With matching tiers, theoretical transfer time is `Cell count / Coil count` seconds. Cell capacities, recipes and energy production remain unchanged. The existing independent shared input/output budgets continue to apply.

`chaosmod-energy-matrix.toml` is a per-world SERVER config. Loading a pre-rebalance configuration upgrades recognised old defaults from both previous presets, preserving other custom rates and Cell capacities. A persisted balance revision prevents reapplying the migration if an administrator later intentionally chooses an old value. Startup writes use the existing watcher guard; no extra file save is issued from the loading event.

## Reality Devourer optics

Optical positions derive from the same template used by structural validation. The singularity is centred on the physical containment rings, rather than the small required-air cavity below their centre.

- Each of the eight emitters attaches to an actual anchor block, on the inward face of its upper plate, with 0.015 blocks of surface clearance.
- The visual singularity follows the shared geometric centre of the two large containment rings, `(48.5, 29.0, 48.5)` in template coordinates. Its body and accretion disk are enlarged together by 3×, and every beam converges to that same exact centre without block-coordinate rounding. The saved functional singularity metadata and construction rules remain unchanged.
- The centre and emitters follow all four structural rotations. Render bounds cover the full structure.
- The core has an opaque event horizon, a luminous surface, a softened accretion disk, containment rings and pulsating volumetric beams.

## Zenith Accelerator optics

The convergence beams now use the four cardinal air channels and guide mouths in the native template, replacing the guessed diagonal endpoints. The reaction object sits in its actual air cavity above the Reaction Core.

The object uses an opaque shaded sphere, a luminous plasma layer and counter-rotating containment lenses. Ring and beam formation is smoothed across state transitions. The palette uses silver, white and lavender.

Both renderers use a shared bounded mesh implementation with three distance-based detail levels. The glow pass uses the main target, additive blending and depth testing without writing depth; opaque bodies write depth separately. Visibility checks use the machine render bounds rather than the terminal position. Effects remain occluded by physical blocks.
